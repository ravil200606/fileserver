# Для чего все это?

У вас когда-нибудь был старый iPad, крепкий, работающий, качественно сделаный? Но старый. И такое усройство
очень не хочется выбрасывать, или убирать на полку, вроде когда-нибудь понадобится (но мы все понимаем что нет,
это почти что выбросить просто лежать будет на полке). 
Это устройство прекрасная читалка, вот только старые программы типа ShortBookReader теперь не могут зацепиться
за библиотеку Flibusta, потому что ее прикрыли.
И я решил сделать небольшой локальный сервер. Запускаем, подключаемся со старого устройства, закачиваем на него книги и читаем.
А книги ложим на файловую систему (какими путями мы их достаем, вопрос второй, и здесь речь не об этом).
Сервер предоставляет страничку со списком, который обновляется автоматически как-только в хранилище добавлена новая книга.
В идеале, я бы хотел сделать его максимально легковесным, чтоб он крутился на устройстве с низким энергопотреблением
и всегда был доступен в рамках моей домашней сети. 

P.S.
Этот проект используется параллельно как учебный в рамках курса OTUS "ИИ для разработчиков", по этому здесь присутствуют директоии на подбие homework.
На работоспособность приложения это не влияет.

## Запуск

Приложение отдаёт все файлы из каталога с книгами. Каталог задаётся при запуске:

- по умолчанию — `~/books`;
- переопределяется переменной окружения `BOOKS_DIR`.

Главная страница показывает таблицу файлов и перечитывает каталог каждые
`FILESERVER_REFRESH_INTERVAL_SECONDS` секунд (по умолчанию 5). Если в каталоге
появились новые файлы, таблица обновится автоматически без перезагрузки страницы.
Клик по имени файла скачивает его через `/file/download?name=<имя файла>`.

Страница разделена на две закладки: «Книги» с таблицей книг и «Архив»
с таблицей файлов, у которых есть расширение `.arch`. В крайней правой колонке
таблицы у каждой книги есть чекбокс для выбора нескольких книг. Чекбокс
в заголовке колонки выбирает все книги, видимые в таблице. Выбор сохраняется
при автообновлении списка.

Над таблицей на вкладке «Книги» есть кнопка «Архивировать». Она неактивна, пока
не выбрана ни одна книга. После нажатия к именам выбранных файлов добавляется
расширение `.arch`, и они пропадают из вкладки «Книги» (например,
`Толстой_Л_Н-Анна Каренина.zip` превращается в
`Толстой_Л_Н-Анна Каренина.zip.arch`).

На вкладке «Архив» над таблицей есть кнопки «Восстановить» и «Удалить». Обе
неактивны, пока не выбран хотя бы один архивный файл:

- «Восстановить» убирает расширение `.arch` из имени файла, и книга возвращается
  на вкладку «Книги»;
- «Удалить» безвозвратно удаляет выбранные файлы из файловой системы.

Скачивание книг с вкладки «Архив» недоступно.

Значения по умолчанию заданы в `src/main/resources/application.yaml`.
Страница использует только локальные CSS и JavaScript — при загрузке не выполняется
запросов к внешним ресурсам (CDN, шрифтам и т. п.). Интерфейс совместим со старыми
Safari (iOS 5.1): используется ES5, `XMLHttpRequest` и CSS без переменных
и современного flexbox.

### Локальный запуск

```bash
# каталог по умолчанию ~/books
./gradlew bootRun

# или явно указать каталог с книгами
BOOKS_DIR=/path/to/books ./gradlew bootRun
```

После запуска откройте `http://localhost:8080/`.

### Формат имён файлов

Файлы книг должны называться по шаблону:

```text
Фамилия_Инициал_Инициал-Название книги.zip
```

Например: `Толстой_Л_Н-Анна Каренина.zip`. В таблице такой файл отображается
как автор «Толстой Л. Н.» и название «Анна Каренина». Название является ссылкой
для скачивания файла.

Если имя не соответствует шаблону, файл всё равно отображается: в колонке
автора будет «—», а в колонке названия — имя файла без расширения.

Строка под заголовком таблицы содержит фильтры по автору и названию.
Поиск начинается после ввода трёх символов, регистр не учитывается.
Если заполнены оба поля, применяются оба условия. Кнопка «×» рядом
с полем очищает соответствующий фильтр.

## Запуск в Docker

В проекте есть многоступенчатый `Dockerfile` (сборка через Gradle wrapper, запуск на JRE 17)
и `docker-compose.yml` для быстрого старта. Каталог с книгами монтируется в контейнер
как `/data` с доступом на запись — это нужно для архивирования книг.

### Требования

- Docker 20.10+ (или Docker Desktop);
- Docker Compose v2 — только если запускаете через `docker compose`.

### Быстрый старт через Docker Compose

1. Создайте каталог с книгами и положите туда файлы:

   ```bash
   mkdir -p books
   cp /путь/к/книгам/* books/
   ```

2. Соберите образ и запустите контейнер:

   ```bash
   docker compose up -d --build
   ```

3. Откройте в браузере `http://localhost:8080/` — на странице будет таблица
   со всеми файлами из `./books`.

Каталог `./books` на хосте монтируется в контейнер как `/data` (с доступом на запись),
а приложение читает его благодаря переменной `BOOKS_DIR=/data`.

Полезные команды:

```bash
docker compose logs -f       # логи
docker compose down          # остановить и удалить контейнер
```

### Запуск через docker run

```bash
# сборка образа
docker build -t fileserver:latest .

# запуск: каталог с книгами монтируется в /data
docker run -d \
  --name fileserver \
  --restart unless-stopped \
  -p 8080:8080 \
  -v "$(pwd)/books:/data" \
  -e BOOKS_DIR=/data \
  -e FILESERVER_REFRESH_INTERVAL_SECONDS=5 \
  fileserver:latest
```

### Переменные окружения

| Переменная                           | По умолчанию                | Назначение                                                          |
|--------------------------------------|-----------------------------|---------------------------------------------------------------------|
| `BOOKS_DIR`                          | `~/books`                   | Каталог с книгами (в образе по умолчанию `/data`)                   |
| `FILESERVER_REFRESH_INTERVAL_SECONDS`| `5`                         | Как часто страница перечитывает список файлов, в секундах           |
| `SERVER_PORT`                        | `8080`                      | Порт приложения внутри контейнера                                   |
| `JAVA_TOOL_OPTIONS`                  | —                           | Дополнительные JVM-параметры, например `-Xmx256m`                   |
| `BOOKS_HOST_DIR`                     | `./books`                   | Только для compose: каталог с книгами на хосте                      |
| `FILESERVER_PORT`                    | `8080`                      | Только для compose: порт на хосте                                   |

Пример запуска с другим портом, каталогом книг и интервалом обновления:

```bash
docker run -d --name fileserver \
  -p 9090:9090 \
  -e SERVER_PORT=9090 \
  -e BOOKS_DIR=/data \
  -e FILESERVER_REFRESH_INTERVAL_SECONDS=10 \
  -e JAVA_TOOL_OPTIONS="-Xmx256m" \
  -v "/mnt/books:/data" \
  fileserver:latest
```

Для compose-запуска порт, каталог на хосте и интервал обновления можно
переопределить переменными `FILESERVER_PORT`, `BOOKS_HOST_DIR` и
`FILESERVER_REFRESH_INTERVAL_SECONDS`:

```bash
FILESERVER_PORT=9090 \
BOOKS_HOST_DIR=/mnt/books \
FILESERVER_REFRESH_INTERVAL_SECONDS=10 \
docker compose up -d
```

### HTTP-эндпоинты

| Метод | Путь                          | Назначение                                      |
|-------|-------------------------------|-------------------------------------------------|
| `GET` | `/`                           | Страница с таблицей книг                        |
| `GET` | `/files`                      | JSON-список книг и интервал обновления          |
| `POST`| `/files/archive`              | Архивирование книг: JSON-массив имён файлов     |
| `GET` | `/archive`                    | JSON-список архивных файлов                     |
| `POST`| `/archive/restore`            | Восстановление архивных файлов                  |
| `POST`| `/archive/delete`             | Удаление архивных файлов                        |
| `GET` | `/file?name=<файл>`           | Метаданные одной книги (JSON)                   |
| `GET` | `/file/download?name=<файл>`  | Скачивание файла из каталога книг               |

Если каталог не существует или пуст, страница покажет, что книг пока нет.
Скачать можно только файлы, лежащие непосредственно в каталоге книг: пути
с `..` и абсолютные пути отклоняются.
